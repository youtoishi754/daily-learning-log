# コンピューティングサービスの本質

## 目的
アプリケーションを実行するための「計算資源（コンピュータ）」を必要なときに必要な分だけ利用する。

## 1. サーバーを用意する

- コンピューティングサービス：アプリケーションを動かすための計算資源を提供するサービス
- Amazon EC2：AWS上に仮想サーバーを作成するサービス
- インスタンス：起動した1台の仮想サーバー

## 2. サーバーを準備する

- AMI（Amazon Machine Image）：OSやソフトウェアをまとめたサーバーのテンプレート
- EC2 Image Builder：AMIを自動作成・更新するサービス

## 3. サーバー性能を選ぶ

- インスタンスタイプ：CPU・メモリなど性能の組み合わせ
- インスタンスファミリー：用途別（汎用・コンピューティング最適化・メモリ最適化など）の分類
- 世代：インスタンスの新旧バージョン
- 属性：CPU、メモリ、GPU、ネットワーク性能などの特徴
- インスタンスサイズ：同じファミリー内での性能・リソース量

## 4. データを保存する

- EBS（Elastic Block Store）：EC2に接続する永続ストレージ
- EBS最適化インスタンス：EC2とEBS間の通信性能を向上させる機能

## 5. 負荷に対応する

- Elastic Load Balancing（ELB）：複数のEC2へアクセスを分散する
- Auto Scaling：アクセス量に応じてEC2を自動で増減する

## 6. コンテナで動かす

- Amazon ECS：Dockerコンテナを管理・実行するサービス

## 7. サーバーを管理しない

- AWS Lambda：イベント発生時にプログラムを実行するサーバーレスサービス
- サーバーレスアーキテクチャ：サーバー管理を意識せずアプリケーションを実行する構成

## 全体像

```text
利用者
   │
   ▼
ELB
   │
   ▼
EC2（Auto Scaling）
   │
   ├── EBS（データ保存）
   └── ECS（コンテナ実行）

または

イベント
   │
   ▼
Lambda
```

## 本質

**AWSのコンピューティングサービスとは、「アプリケーションを動かすための実行環境を、用途や負荷に応じて柔軟に提供するサービス群」である。**

- EC2：サーバーを借りて動かす
- ECS：コンテナで動かす
- Lambda：サーバーを意識せず動かす
- ELB：アクセスを分散する
- Auto Scaling：必要な台数を自動で調整する
- EBS：データを永続的に保存する
