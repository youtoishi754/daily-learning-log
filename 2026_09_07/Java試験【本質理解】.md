# implements・sealedクラス・ポリモーフィズム・コレクション・コレクションフレームワーク・ジェネリクス

## implements

### 単語の意味
クラスがインターフェースを実装するときに使用するキーワード。

### 本質理解
`extends`が「クラスを継承する」のに対して、`implements`は「インターフェースで決められたルールを実装する」。

```text
interface Animal
├─ eat()
└─ move()

      ↓ implements

class Dog
├─ eat() ← 実装
└─ move() ← 実装
```

```text
extends
→ クラスを継承する

implements
→ インターフェースを実装する
```

---

## sealedクラス

### 単語の意味
継承できるクラスを明示的に制限するクラス。

### 本質理解
「誰でも自由に継承してよい」状態にせず、**どのクラスが継承できるかをあらかじめ決める**。

```java
sealed class Animal permits Dog, Cat {
}
```

```text
Animal
 ├─ Dog  ← 継承OK
 ├─ Cat  ← 継承OK
 └─ Bird ← 継承不可
```

`final`が「継承を禁止する」のに対して、`sealed`は「継承できる相手を限定する」。

## ポリモーフィズム（Polymorphism）

### 単語の意味
「多態性」。同じ型として扱いながら、実際のオブジェクトによって異なる処理を実行できる仕組み。

### 本質理解
**「同じ命令を出しても、実体によって動作が変わる」**。

```text
Animal animal

      ↓

Dog  → eat() → 犬の処理
Cat  → eat() → 猫の処理
```

```java
Animal animal = new Dog();
animal.eat();
```

`animal`は`Animal`型として扱っているが、実際のオブジェクトは`Dog`なので、`Dog`でオーバーライドした`eat()`が実行される。

```text
親の型で扱う
      ↓
実際のオブジェクトに応じて
      ↓
適切な処理が実行される
```

## コレクション（Collection）

### 単語の意味
複数のオブジェクトやデータをまとめて管理する仕組み。

### 本質理解
配列のように複数のデータを扱うための仕組みだが、Javaでは用途に応じてさまざまなデータ構造を使い分けられる。

```text
コレクション
├─ List  → 順番を保持
├─ Set   → 重複を許さない
└─ Map   → キーと値で管理
```

---

## コレクションフレームワーク

### 単語の意味
Javaで複数のデータを効率的に管理するためのクラスやインターフェースの仕組み全体。

### 本質理解
**データの入れ物を用途に応じて選べるJava標準の仕組み。**

```text
Collection Framework
│
├─ List
│  ├─ ArrayList
│  └─ LinkedList
│
├─ Set
│  ├─ HashSet
│  └─ TreeSet
│
└─ Map
   ├─ HashMap
   └─ TreeMap
```

例えば、

```text
順番が必要
→ List

重複を避けたい
→ Set

キーと値で管理したい
→ Map
```

---

## ジェネリクス（Generics）

### 単語の意味
クラスやメソッドなどで扱うデータ型を、後から指定できる仕組み。

### 本質理解
**「この入れ物には、この型のデータだけ入れる」とコンパイル時に指定する仕組み。**

```java
List<String> names;
```

これは、

```text
names
 ↓
Stringだけを入れるList
```

という意味。

```java
List<Integer> numbers;
```

なら、

```text
numbers
 ↓
Integerだけを入れるList
```

となる。

### ジェネリクスのメリット

```text
型を指定
 ↓
間違った型を入れにくい
 ↓
コンパイル時にエラーを発見
 ↓
安全にデータを扱える
```

---

# 関係整理

```text
implements
→ インターフェースのルールを実装

sealed
→ 継承できるクラスを制限

ポリモーフィズム
→ 同じ型で扱い、実体に応じて処理を変える

コレクション
→ 複数のデータをまとめて管理

コレクションフレームワーク
→ List・Set・Mapなどのデータ管理機能の体系

ジェネリクス
→ コレクションなどで扱う型を指定
```

特にコレクションとジェネリクスは、

```text
List<String>
    ↑    ↑
    │    └─ String型を扱う
    │
    └─ Listというデータ構造
```

と考えると理解しやすい。
