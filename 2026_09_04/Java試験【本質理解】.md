# レコードクラス・record・コンポーネント・抽象クラス・実装・抽象メソッド

## レコードクラス（Record Class）

### 単語の意味
データを保持することを主目的としたクラス。

### 本質理解
フィールド・コンストラクタ・getter相当のメソッド・`equals()`・`hashCode()`・`toString()`などの定型的なコードを簡潔に記述できる。

```text
通常のクラス
→ データを保持するためのコードを自分で多く記述

レコードクラス
→ データ保持に必要なコードをJavaが自動生成
```

---

## record

### 単語の意味
レコードクラスを宣言するためのJavaのキーワード。

### 本質理解
「このクラスは主にデータを保持するためのクラス」ということを簡潔に宣言する。

```java
record User(String name, int age) {
}
```

---

## コンポーネント（Record Component）

### 単語の意味
レコードクラスの宣言部分に記述するデータ項目。

```java
record User(String name, int age) {
}
```

この場合、

```text
String name
int age
```

がコンポーネント。

### 本質理解
レコードが保持するデータを定義する部分。

```text
record User(String name, int age)
              ↓          ↓
          コンポーネント
```

---

## 抽象クラス（Abstract Class）

### 単語の意味
`abstract`を付けて宣言する、継承されることを前提としたクラス。

### 本質理解
共通する処理や設計を親クラスにまとめ、子クラスに具体的な実装を任せるためのクラス。

```text
抽象クラス
    ↓ 継承
┌───┴───┐
子クラス 子クラス
```

抽象クラスは直接インスタンス化できない。

```text
new AbstractClass()
        ↓
    コンパイルエラー
```

---

## 抽象メソッド（Abstract Method）

### 単語の意味
処理内容を記述せず、メソッドの宣言だけを行うメソッド。

```java
abstract void eat();
```

### 本質理解
「この処理を持つこと」を子クラスに要求し、具体的な処理は子クラスで実装させる。

```text
抽象メソッド
    ↓
「eat()を実装してください」
    ↓
子クラス
    ↓
具体的な処理を実装
```

---

## 実装

### 単語の意味
決められたメソッドの具体的な処理を書くこと。

### 本質理解
抽象メソッドなどで定義された「何をするか」に対して、「具体的にどうするか」をコードとして記述すること。

```text
抽象メソッド
eat()
 ↓
子クラスで実装
 ↓
eat() {
    System.out.println("食べる");
}
```

---

# 抽象クラス・抽象メソッド・実装の関係

```text
抽象クラス
   │
   ├─ 共通処理
   │    ↓
   │   そのまま継承
   │
   └─ 抽象メソッド
        ↓
   「処理を実装して」
        ↓
     子クラス
        ↓
      実装
        ↓
   具体的な処理
```

つまり、

**抽象クラス = 共通部分と設計をまとめる親クラス**

**抽象メソッド = 子クラスに実装を要求するメソッド**

**実装 = 抽象メソッドの具体的な処理を書くこと**

**record = データを保持するクラスを簡潔に定義する仕組み**

という関係。
