# AWSインフラの基本構成

## グローバルインフラストラクチャ
AWSが世界中に展開しているクラウド基盤。リージョン、アベイラビリティゾーン（AZ）、エッジロケーションなどで構成される。

## マルチAZ（Multi-AZ）
複数のAZにシステムを配置し、障害発生時もサービスを継続できる高可用性構成。

## レイテンシー（Latency）
データ送受信にかかる時間（通信の遅延）。利用者との距離が近いほど小さくなる。

## エッジロケーション（Edge Location）
CloudFrontなどが利用する拠点。利用者に近い場所からコンテンツを配信し、レイテンシーを低減する。

## Web＋DBシステムのマルチAZ基本構成

```text
利用者
   │
   ▼
CloudFront（エッジロケーション）
   │
   ▼
ELB
 ┌───────┴───────┐
 ▼               ▼
EC2（AZ1）     EC2（AZ2）
      │
      ▼
RDS（Multi-AZ）
      │
      ▼
S3（画像・ファイル保存）
```

### 構成の役割

- CloudFront：利用者に近い場所から配信し高速化
- ELB：アクセスを複数EC2へ負荷分散
- EC2：Webアプリケーションを実行
- RDS（Multi-AZ）：データベースを冗長化し障害に備える
- S3：画像やファイルを保存

### 学習ポイント

- AWSは世界中にリージョンを持つ（グローバルインフラストラクチャ）
- 各リージョンは複数のAZで構成される
- マルチAZで障害に強いシステムを構築する
- エッジロケーションを利用すると通信遅延（レイテンシー）を削減できる
- Webシステムでは「ELB → EC2 → RDS」の構成が基本となる

# AWS エッジ・ハイブリッドクラウドの本質

## 課題
利用者がAWSリージョンから遠いと、通信遅延（レイテンシー）が発生し、表示や処理が遅くなる。

## Amazon CloudFront
利用者に近いエッジロケーションからコンテンツを配信し、通信を高速化するCDNサービス。

## Lambda@Edge
CloudFrontのエッジロケーションでプログラムを実行し、利用者の近くで処理を行うサービス。

## AWS Local Zones
AWSリージョンの機能を利用者の近くまで拡張し、低レイテンシーでアプリケーションを実行できるサービス。

## AWS Outposts
AWSのインフラをオンプレミス環境へ設置し、社内でもAWSと同じ環境を利用できるサービス。

## 全体のイメージ

利用者から近い順

利用者
↓
CloudFront（コンテンツを高速配信）
↓
Lambda@Edge（近くで処理）
↓
Local Zones（近くでアプリ実行）
↓
AWSリージョン（通常のAWS環境）
↓
Outposts（社内にAWS環境を構築）

## 本質

- CloudFront：データを近くから配信する
- Lambda@Edge：処理を近くで実行する
- Local Zones：AWS自体を近くへ配置する
- Outposts：AWSを自社へ持ってくる

# Amazon VPCの本質

## 目的
AWS上に、自分専用の安全なネットワークを構築する。

## 1. ネットワークを作る

- VPC：AWS上に専用ネットワークを作る
- CIDRブロック：利用するIPアドレス範囲を決める
- サブネット：用途ごとにネットワークを分割する

## 2. サーバーを配置する

- パブリックサブネット：インターネット公開用（Webサーバーなど）
- プライベートサブネット：内部システム用（DBなど）
- 3AZ構成：複数AZへ配置して障害に強くする

## 3. 外部と接続する

- IGW：インターネットへ接続する
- NAT Gateway：内部サーバーだけ外部へ通信する
- VGW：オンプレミスとVPN接続する

## 4. 通信経路を決める

- ルートテーブル：通信先を決定する

## 5. 通信を守る

- セキュリティグループ：インスタンス単位のファイアウォール
- ネットワークACL：サブネット単位のファイアウォール
- インバウンド：受信通信を制御
- アウトバウンド：送信通信を制御

## 6. AWSサービスへ安全に接続する

- VPCエンドポイント：インターネットを使わずAWSサービスへ接続
- ゲートウェイエンドポイント：S3・DynamoDB専用
- AWS PrivateLink：他VPCやサービスへプライベート接続

## 7. 他ネットワークと接続する

- VPCピアリング：2つのVPCを直接接続
- AWS Transit Gateway：多数のVPCを一元接続
- AWS Direct Connect：専用線でAWSへ接続
- AWS Direct Connect Gateway：複数VPC・リージョンへ接続
- AWS Site-to-Site VPN：拠点間VPN接続
- AWS Managed VPN：AWS管理のVPNサービス
- AWS Client VPN：PCからAWSへVPN接続
- SSL-VPN：SSL/TLSを利用したVPN方式

## 8. 運用・監視

- VPCフローログ：通信ログを記録する

## 9. 可用性

- SPOF（単一障害点）：障害で全体停止する箇所
- マルチAZ・冗長構成でSPOFをなくす

## 全体像

```text
Internet
    │
   IGW
    │
──────────────
 VPC
 ├─ Public Subnet
 │    └─ Webサーバー
 │
 ├─ Private Subnet
 │    ├─ Appサーバー
 │    └─ DBサーバー
 │
 └─ NAT Gateway
      │
      ▼
 Internet

他ネットワーク
    │
 VPN / Direct Connect
    │
   VGW / Transit Gateway
```

### 本質

**VPCとは「AWS上に安全な会社のネットワークを作り、必要な相手とだけ通信できるよう設計する仕組み」である。**
