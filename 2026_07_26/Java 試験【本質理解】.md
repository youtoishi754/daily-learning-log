# JVM（Java Virtual Machine）

## 本質理解

Java最大の特徴は、

**「一度コンパイルすれば、どのOSでも動作できる」**

ことである。

---

## 1. JVMがない場合

一般的なプログラムはOSごとに対応が必要。

```
C言語など

ソースコード
      │
      ▼
  コンパイル
      │
      ▼
Windows用実行ファイル

      ↓

Windowsで動作
```

Linuxの場合：

```
ソースコード
      │
      ▼
Linux用にコンパイル
      │
      ▼
Linuxで動作
```

Macの場合：

```
ソースコード
      │
      ▼
Mac用にコンパイル
      │
      ▼
Macで動作
```

つまりOSごとに別々の実行形式を作る必要がある。

---

# 2. Javaの場合

JavaはOSとの間にJVMを置く。

```
Javaソースコード

       .java
         │
         │ javac
         ▼

    バイトコード

       .class
         │
         │ javaコマンド
         ▼

        JVM

 ┌────────┼────────┐
 ▼        ▼        ▼

Windows  Linux    Mac
```

JVMがOSごとの差を吸収する。

---

# 3. JVMの役割

```
Javaプログラム

        ↓

       JVM
   （Java専用の仮想コンピュータ）

        ↓

 ┌──────┬──────┬──────┐
 ▼      ▼      ▼
Windows Linux  Mac
```

JVMは、

「Javaの命令を、それぞれのOSが理解できる形で実行する」

役割を持つ。

---

# 4. JVMを例えると

```
日本語
  │
  ▼
翻訳者（JVM）
  │
  ▼
英語・中国語・フランス語
```

Javaプログラム：

→ 日本語

JVM：

→ 翻訳者

OS：

→ 外国人

という関係。

Java開発者はOSごとの違いを直接考えなくてもよい。

---

# 5. Java実行までの流れ

```
① ソースコードを書く

Hello.java

        ↓

② javacでコンパイル

        ↓

Hello.class

（バイトコード）

        ↓

③ javaコマンド実行

        ↓

④ JVMが読み込む

        ↓

⑤ プログラム実行
```

---

# 6. Javaの本質

Javaの本質は、

```
プログラム
    ↓
バイトコード
    ↓
JVM
    ↓
OS
```

という中間層を作ったこと。

この仕組みにより、

```
Write Once
Run Anywhere

（一度書けばどこでも動く）
```

を実現している。

---

# 7. 関連用語

| 用語 | 役割 |
|---|---|
| .java | 人間が書くJavaソースコード |
| javac | .javaを.classへ変換するコンパイラ |
| .class | JVMが実行するバイトコード |
| バイトコード | JVM用の中間コード |
| JVM | バイトコードを実行する仮想マシン |
| javaコマンド | JVMを起動して実行するコマンド |
