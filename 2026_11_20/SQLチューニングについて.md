# SQLチューニング・インデックス・B+Tree

## 1. SQLチューニング

### 用語の意味
SQLの実行効率を改善し、処理時間やデータベースへの負荷を軽減すること。

### 本質理解
同じ検索結果でも、データの探し方によって処理速度は変わる。

- 不要なデータ取得を減らす
- インデックスを適切に設定する
- JOINやWHERE句を見直す
- EXPLAINで実行計画を確認する

### 関連用語
| 用語 | 意味 |
|---|---|
| EXPLAIN | SQLの実行計画を確認する |
| Full Table Scan | テーブル全体を走査する |
| オプティマイザ | SQLの実行方法を選択する |

## 2. インデックス（Index）

### 用語の意味
データベースの検索を効率化するための索引。

### 本質理解
書籍の索引と同じように、目的のデータの位置を効率よく探す仕組み。

```sql
CREATE INDEX idx_users_age
ON users(age);
```

`age` カラムにインデックスを作成する例。

インデックスを利用することで、テーブル全体を走査せずに検索できる場合がある。

### メリット・デメリット

| メリット | デメリット |
|---|---|
| SELECTの高速化 | ストレージ容量を消費する |
| JOINの効率化 | INSERTの負荷が増える |
| 範囲検索の効率化 | UPDATE・DELETEの負荷が増える場合がある |

※ インデックスは多ければ良いわけではなく、検索頻度や更新頻度を考慮して設計する。

## 3. B+Tree（B+木）

### 用語の意味
データベースのインデックスなどに利用される、平衡木構造のデータ構造。

### 本質理解
複数のキーを使って検索範囲を段階的に絞り込み、目的のデータを効率よく探す仕組み。

- 1つのノードに複数のキーを保持する
- 複数の子ノードに分岐する
- 木の高さを抑えることで検索効率を高める
- 検索計算量は一般に O(log N)

## 4. B+Treeの構造

| 構造 | 役割 |
|---|---|
| Root Node | 検索の開始地点 |
| Branch Node | 検索範囲を絞り込む |
| Leaf Node | インデックスキーとレコードへの参照を保持する |

### 本質理解

- すべてのリーフノードが同じ深さに配置される
- リーフノード同士が連結されている
- リーフノードを順番にたどることで範囲検索を効率化できる

### 範囲検索の例

```sql
SELECT *
FROM users
WHERE age BETWEEN 20 AND 30;
```

1. B+Treeから20の位置を検索する
2. 該当するリーフノードに到達する
3. 連結されたリーフノードを順番にたどる
4. 30を超えたら検索を終了する

## 5. 全体の関係性

- SQLチューニング：SQLの処理効率を改善する
- インデックス：データを効率よく検索するための索引
- B+Tree：インデックスを実現する代表的なデータ構造
- Root・Branch・Leaf：B+Treeを構成するノード
