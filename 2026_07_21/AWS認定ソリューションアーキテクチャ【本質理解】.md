# AWSストレージサービスの本質

## 目的
アプリケーションのデータを用途に応じた最適な方法で保存する。

## 1. ストレージの種類を理解する

### ブロックストレージ
サーバーのディスクとして使用するストレージ。

→ Amazon EBS

### ファイルストレージ
複数のサーバーで同じファイルを共有するストレージ。

→ Amazon EFS

### オブジェクトストレージ
画像・動画・バックアップなどを大量保存するストレージ。

→ Amazon S3

---

## 2. EC2のディスクとして使う（Amazon EBS）

### Amazon EBS
EC2専用の永続ブロックストレージ。

### ボリュームタイプ

- SSD：高速アクセス向け
- プロビジョンドIOPS SSD：高いIO性能が必要なDB向け
- スループット最適化HDD：大量データ処理向け
- Cold HDD：低コスト・アクセス頻度が低いデータ向け
- マグネティック：旧世代のHDD

### 性能

- IOPS：1秒間に処理できるI/O回数
- ベースライン性能：常に保証される性能
- バースト性能：一時的に性能を向上できる
- バーストバランス：利用可能なバースト性能の残量

### 運用

- サイジング：用途に応じて容量・性能を選択する
- EBSの拡張・変更：容量や性能を停止せず変更可能
- 可用性・耐久性：AZ内で高い耐障害性を持つ
- セキュリティ：暗号化やIAMで保護する

---

## 3. 複数サーバーで共有する（Amazon EFS）

### Amazon EFS
複数EC2から同時利用できるファイルストレージ。

### 接続

- amazon-efs-utils：EFSを簡単にマウントするツール
- マウントターゲット：各AZからEFSへ接続する入口

### ストレージクラス

- EFS Standard：高頻度アクセス向け
- EFS One Zone：単一AZ・低コスト
- EFS Standard-IA：低頻度アクセス
- EFS One Zone-IA：単一AZ・低頻度アクセス

### パフォーマンスモード

- 汎用パフォーマンス：低遅延
- 最大I/Oパフォーマンス：大量アクセス向け
- PercentIOLimit：利用中のI/O性能割合

### スループットモード

- バーストスループット：容量に応じ自動変化
- プロビジョニングスループット：性能を固定指定
- エラスティックスループット：アクセス量に応じ自動調整
- BurstCreditBalance：バースト利用可能量

---

## 全体像

```text
            データ保存
                 │
     ┌──────────┴──────────┐
     │                     │
EC2のディスク          複数サーバー共有
     │                     │
 Amazon EBS           Amazon EFS
     │                     │
高速・DB向け         ファイル共有
```

## 本質

- **EBS**：1台のEC2のディスクとして使うストレージ
- **EFS**：複数EC2で共有するストレージ
- **S3**：大量のファイルを保存するストレージ

**AWSでは「何を保存するか」ではなく、「どう使うか」でストレージを選択することが重要である。**

# AWSストレージ・データベースの本質

## 目的
データを「安全に保存・共有・保護し、必要なときに素早く利用できる」ようにする。

---

# 1. オブジェクトストレージ（Amazon S3）

## Amazon S3（Simple Storage Service）
大量のファイルを保存するオブジェクトストレージ。

### 基本

- バケット：オブジェクトを保存する入れ物
- オブジェクト：保存するファイル
- メタデータ：オブジェクトの情報（作成日時・種類など）

### データ整合性

- 強い整合性方式：保存・更新後すぐに最新データを参照できる

---

## 2. 保存期間に応じてストレージを選ぶ

### 頻繁にアクセス

- S3 Standard

### たまにアクセス

- S3 Standard-IA

### 単一AZ・低コスト

- S3 One Zone-IA

### 自動最適化

- S3 Intelligent-Tiering

### アーカイブ

- S3 Glacier Instant Retrieval
- S3 Glacier Flexible Retrieval
- S3 Glacier Deep Archive

---

## 3. 保存データを自動管理

- ライフサイクル管理：保存期間に応じて自動管理
- 移行アクション：別ストレージクラスへ移動
- 有効期限アクション：不要データを自動削除

---

## 4. データを保護する

- バージョニング：過去バージョンを保存
- オブジェクトロック：削除・変更を防止
- リテンションモード：一定期間保護
- ガバナンスモード：権限があれば解除可能
- s3:BypassGovernanceRetention：ガバナンス解除権限
- コンプライアンスモード：誰も解除できない
- リーガルホールド：法的理由で保護
- s3:PutObjectLegalHold：リーガルホールド設定権限
- MFA Delete：多要素認証がないと削除できない

---

## 5. アクセス制御

- アクセスポイント：用途別アクセス入口
- バケットポリシー：アクセス権限設定
- アタックサーフェス：攻撃対象となる範囲
- 署名付きURL：期限付きアクセスURL

### ブロックパブリックアクセス

- BlockPublicAcls
- IgnorePublicAcls
- BlockPublicPolicy
- RestrictPublicBuckets

→ 誤公開を防ぐ設定

---

## 6. 大容量データ転送

- マルチパートアップロード：分割して高速アップロード
- S3 Transfer Acceleration：世界中から高速転送
- S3 Select：必要データだけ取得
- S3 Glacier Select：アーカイブから必要データだけ取得

---

# 7. ファイルストレージ

## Amazon FSx

用途別マネージドファイルシステム

- FSx for Windows File Server
- FSx for Lustre

---

# 8. オンプレミス連携

## AWS Storage Gateway

オンプレミスとAWSストレージを接続

- ファイルゲートウェイ
- ボリュームゲートウェイ
- キャッシュ型ボリューム
- 保管型ボリューム
- テープゲートウェイ

---

## 9. セキュリティ

- CHAP認証：ストレージ接続認証
- データ暗号化：保存データを保護
- 通信の暗号化：通信内容を保護

---

# 10. データベース

## RDB（リレーショナルデータベース）

表形式でデータを管理するデータベース

- SQL：RDBを操作する言語
- NoSQL：柔軟なデータベース

---

## Amazon RDS

AWSが管理するリレーショナルデータベース

### 可用性

- マルチAZ構成
- リードレプリカ

### バックアップ

- 自動バックアップ
- 手動スナップショット
- データのリストア
- ポイントインタイムリカバリー

### セキュリティ

- ネットワークセキュリティ
- データ暗号化

---

## Amazon Aurora

AWSが提供する高性能・高可用性のRDS互換データベース。

---

# 全体像

```text
保存したい
      │
 ┌────┴─────┐
 │          │
ファイル     データベース
 │          │
S3         RDS
 │          │
長期保存     Aurora
 │
FSx
 │
Storage Gateway
```

## 本質

- **S3**：ファイルを保存する
- **FSx**：ファイルを共有する
- **Storage Gateway**：オンプレミスとAWSをつなぐ
- **RDS / Aurora**：データを検索・更新しやすい形で管理する

**AWSでは「保存するデータの種類」と「アクセス頻度・用途」に応じて最適なストレージやデータベースを選択することが重要である。**
